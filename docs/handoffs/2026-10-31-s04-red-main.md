## What is red, and why

**`coverage` — `internal/store coverage is 33%, below the 84% floor`.** This is a bug in the CI script, not in the
code. The per-package average is computed with `grep "cairn/$pkg/"`, which also matches the generated subpackage
`internal/store/db/` (sqlc output, no tests), so the two get averaged together.

Fix in `.github/workflows/ci.yml`, in the "Critical packages must stay covered" step:

```bash
pct=$(go tool cover -func=/tmp/cover.out \
  | grep "cairn/$pkg/" \
  | grep -v "/db/" \
  | awk '{gsub(/%/,"",$3); s+=$3; n++} END {if (n) printf "%.0f", s/n; else print 0}')
```

Generated code should not count toward a floor either way, so excluding it is the honest fix rather than lowering
the number.

**`codeql` — `Extraction failed for all discovered Go projects`.** The `codeql` job is the only one that does not
run `actions/setup-go`, so it uses whatever Go the runner image ships. That is now Go 1.27, and CodeQL 2.27.3
cannot read its export data (the same class of failure that golangci-lint v2.12.1 had locally, which is why this
commit pins v2.15.0). Add the setup step to both the `codeql` job in `ci.yml` and `codeql-weekly` in
`nightly.yml`, so the extractor sees the same Go as every other job:

```yaml
      - uses: actions/setup-go@40f1582b2485089dde7abd97c1529aa768e1baff # v5
        with:
          go-version-file: ${{ env.GO_VERSION_FILE }}
          cache: true
```

If the new Go version becomes the pin, this fix changes shape: CodeQL needs a release that understands it before
the toolchain moves. That is a decision for Autumn, not for a build agent.
