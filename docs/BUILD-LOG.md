## 2026-10-31, planning complete
The plan, the specs (`ENTRY_CARD`, `PROTOCOL`, `UPDATE`), the question banks, the decisions draft, the testing and

## 2026-10-31, S00.1-S00.4, the walking skeleton

**Built.** `go.mod` (module `github.com/AutumnsGrove/cairn`, `go 1.26`), the Makefile (`check`, `test`,
`e2e`, `gen`, `web`, `web-check`, `guard`, `nocgo`, `fuzz-smoke`), `.golangci.yml`, `.editorconfig`,
`STACK.md`, `SECURITY.md`, `CODEOWNERS`, the architecture test, the server skeleton, the embedded frontend,
the world harness and `cmd/cairn-dev`.

**What is true now.** `GET /healthz` answers exactly `{"status":"ok","version":"dev"}`; the Host check refuses
anything off the allow-list on every route; a state-changing request or a socket upgrade without our own
`Origin` is refused; unknown `/api` paths and wrong methods answer the JSON envelope; a hostile header over
16 KiB is refused; the frontend is embedded and served with brotli or gzip chosen from what the client
accepts; SIGTERM drains and exits 0. The architecture test fails the build on any import that breaks
`BUILD.md` 4, proved by adding `domain -> store` and watching it go red.

**Learned, for the next agent.**

- **SvelteKit 3 moved configuration out of `svelte.config.js`** into the `sveltekit()` plugin in
  `vite.config.ts`, and route options now travel as `export const config`. The old file is a hard build error
  (`config_file_unsupported`). `tsconfig.json` must extend `"$app/tsconfig"`.
- **A stray `~/node_modules/cookie` on this machine shadowed pnpm's copy** during the post-build route
  analysis, which resolves from `.svelte-kit/output`, not from Kit's own directory. `cookie` is therefore an
  explicit dev dependency: it is a genuine phantom dependency of the analysed output, not a workaround.
- **`svelte-check` was green while the page rendered unstyled**, because deleting `+layout.ts` took the
  `app.css` import with it. Rendered and looked, as the mockup rule says.
- **The guard script caught two of its own rules** on first run: a test calling `http.Get` and one using
  `http.DefaultClient`. Both were rewritten against a context, and the rules stay strict.
- The `drift` CI job waits for S02, because there is no `api/` contract to regenerate yet.

**The first CI run found three things, all fixed in the same slice.** `web` could not start pnpm, because the
app never said which version it uses (it does now, and the action is told where `web/package.json` is). `nocgo`
listed `runtime/cgo` because it ran `go list` with cgo on, which is the opposite of what it claims to check.
`internal/config` was at 65% coverage, below the floor the job asserts, so the derived origin list and the
startup consistency check got tests.

**A false positive was removed from history rather than allowlisted.** gitleaks flagged the RFC 6455 handshake
key in a test as a generic API key. The commit was amended to build the nonce from a low-entropy string, so no
allowlist has to hide a test file from the scanner forever. Nothing but the branch tip had been published. The
guard script also stopped running its own `gitleaks`: one scanner, in CI and in `make gitleaks`, so the two can
never disagree about the rules or the version.

**CI is green on `main`** for all seven jobs: `go`, `nocgo`, `coverage`, `web`, `e2e`, `guard`, `codeql`
(`deps` is pull-request only until S13). Getting there took five runs, and every failure was a real one: the
pnpm version, the cgo check running with cgo on, config coverage, missing Node type definitions, and a Prettier
format. The screenshot baseline needed a different fix: Chromium and WebKit on Linux rasterise glyphs 2% away
from macOS, so each platform now has its own baseline and the Linux ones were generated by the `baselines`
workflow on the runner that compares against them.

**Live checks left for Autumn:** the repository settings in [`REPO-SETTINGS.md`](REPO-SETTINGS.md), which are
the only part of S00 that cannot live in the repository.

## 2026-10-31, S03, the domain core

**Built.** `internal/domain`: the rating parser (quarter-stars, snapping, Unicode digits), date resolution
against the phone's zone, the span locator with its normaliser and closest-passage search, format cues, title
matching, the merge, and the save guard with the entry and diff types. 95.6% coverage, two fuzz targets, and
six property tests over generated input.

**What is true now.** A quote the operator never wrote cannot become a body: it is dropped and logged, and
`ValidateForSave` refuses an extracted body whose spans are not in her messages. A one-word slip or a homoglyph
lands on her own wording; a short quote has to match exactly, because one edit turns "dune" into "done". A merge
never takes a web field without an accept tap, never loses a trusted field, and is idempotent.

**Learned, for the next agent.**

- **Fuzzing paid immediately, three times.** `findExact` could spin forever when a quote only appeared inside
  longer words; the normaliser appended one origin offset per *rune* while writing *bytes*, which shifted every
  later span; and the Unicode digit helper counted back to a block start, which returns 10 for the mathematical
  digits because their blocks abut. None of these would have been found by the example tests, and all three are
  now regression seeds under `testdata/fuzz/`.
- **A lookalike is not a failure to match.** The first instinct was to reject a Cyrillic "е" outright. The
  invariant is about what is *stored*, not what is matched: matching it and storing the source's own word is
  both safer and more useful for screenshot imports.
- **`Compose` needs a separator rule, and the invariant needs to survive it.** Joining two passages with a
  newline adds a character she did not write, so containment is proved per span and the newline is documented in
  `ENTRY_CARD.md` rather than quietly appearing in a saved body.
- **The thresholds are starting values.** The cutoff (0.72) and the minimum fuzzy length (12) are guesses with a
  test, not measurements. G4 replaces them with real odds.

## 2026-10-31, S02, the contract

**Built.** `api/events.schema.json`, `api/openapi.yaml`, `api/error-codes.json`, 34 golden examples in
`api/examples/`, `internal/contract` (the Go validator and the generated code registry), the TypeScript types
and validator under `web/src/lib/contract/`, `tools/gen`, `web/scripts/gen-contract.mjs`, `make gen`, and the
`drift` CI job.

**What is true now.** A frontend agent can build a screen from the generated types and an example without
reading server code; a backend agent can build a handler from the schema without reading the UI. The same
schema document validates in Go (santhosh-tekuri/jsonschema) and in TypeScript (ajv), so a fixture cannot pass
on one side and fail on the other. `make gen` is idempotent, and CI fails when it is not.

**Learned, for the next agent.**

- **A colon in an unquoted YAML scalar is a parse error**, which `openapi-typescript` found in a `summary`. The
  contract files are linted by being parsed, so a typo fails the generator rather than the frontend.
- **Two ajv entry points cannot share a `$id`.** The schema is compiled twice, once for server events and once for
  client messages, so the `$id` is dropped when the entry point is attached.
- **Generated files must be excluded from ESLint and Prettier**, or every run of `make gen` fights the formatter
  and the drift check never settles. They are still type-checked by `svelte-check`.
- **The Go event structs wait for S07.** Nothing calls them yet, and generated code that nothing calls is where
  drift hides. The drift job covers what is generated today.

## 2026-10-31, S04 in progress, the data layer's foundations

**Built so far.** `internal/store`: the schema with every table and index from PLAN.md 6, eight triggers, the
migration runner (append-only, positional, one transaction per file, refuses a newer file), the doctor (integrity,
trigger presence and permissions) and its active probe, the writer/reader split, and `sqlc` with 45 queries
generated into `internal/store/db`. `make gen` now regenerates the SQL code too, and `drift` covers it.

**What is true now.** No SQL the application, a test or a manual shell can run will delete a review, rewrite a
revision, edit a source snapshot, or drop an answer. A source may be accepted exactly once. A saved entry never
returns to a draft. A process killed mid-transaction leaves a database that still opens, passes the integrity
check, and has none of the half-written row. A database from a newer binary refuses to open.

**Still to do in S04.** The repository layer over the generated queries (works, entries, answers, revisions,
sessions, events, media, mirrors), the cursor-paginated library and drafts queries with `EXPLAIN QUERY PLAN`
tests, event-log compaction, and the restore path. The slice stays "in progress" until those land.

**Learned.**

- **`sqlc` and repeated named arguments disagree.** A named argument used three times in one query produced three
  `?` placeholders but one struct field, so the driver got fewer arguments than it wanted. The fix was a
  row-value cursor comparison with positional parameters, which also lets SQLite walk the index.
- **An empty table fires no trigger.** A probe that deletes from `entries` before any row exists passes whether or
  not the protection is there, so the doctor writes probe rows inside a transaction and rolls the whole thing back.
- **A failed migration must not stamp its version.** The schema change and `PRAGMA user_version` share one
  transaction, and a test asserts the version does not move when the SQL is broken.
